## 蒸餾 Berne Ting Workflow Agent 的反思

這次作業我選擇「個人工作流整理型」作為 Agent 的設計方向，而不是建立百科全書型的個人知識庫。原因是百科全書型設定雖然看起來完整，但很容易變得過大、過散，也不一定能真正支援日常工作。相較之下，工作流型 Agent 更接近我實際使用 AI 的方式：我需要的不是一個知道所有事情的分身，而是一個能理解我的語氣邊界、判斷流程與常見任務的協作者。

在蒸餾過程中，我發現最容易形式化的是可重複的工作流程。例如學術寫作可以拆成判斷段落功能、保留原意、強化主題句、移除重複、避免過度推論；審稿分析也可以拆成方法、報告、統計、邏輯與表達等層次。這些流程本來就帶有明確步驟，因此比較容易寫成 Agent 可以執行的規則。教學設計也有類似特徵，可以從學生背景、學習目標、活動步驟與評分標準逐步展開。

比較困難的是語氣。我的語氣並不是單純的「溫和」或「理性」，而是包含某種分寸感：可以有情感，但不要煽情；可以有文學性，但不要堆砌華麗詞；可以批評，但要客觀、克制、有界線。這些特徵很難只用幾個形容詞描述，必須透過避免事項、修正規則與測試對話慢慢逼近。尤其是「不要太 AI 化」這件事，其實不是單一規則，而是牽涉到句型是否太工整、結尾是否太像總結、情緒是否被放大，以及文字是否失去生活中的不完整感。

我也意識到，「蒸餾人」並不等於複製一個人。Agent 能模擬的是我某些可描述、可重複、可規則化的工作習慣，而不是完整的自我。真正有價值的部分，不是讓 AI 假裝成我，而是讓它在特定任務中更理解我的工作方式，減少反覆說明的成本。換句話說，這個 Agent 比較像一套工作界面，而不是一個完整人格。

因此，這次我將核心人格與語氣規則放入 SOUL.md，將背景與偏好放入 USER.md，將主要工作流程整理在 AGENTS.md，並以 personal_voice_post_writer.skill 作為具體示範。這個 Agent 的目的不是全能，而是可用、可調整、可逐步擴充。未來如果要繼續發展，我會先增加學術寫作與審稿分析兩個 skill，而不是急著加入更多知識內容。這也讓我重新理解 Agent 設計的重點：不是把所有東西塞進去，而是讓最常做的事情變得更穩定、更清楚，也更接近自己的工作方式。
